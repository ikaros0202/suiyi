# 新版架构边界

当前依据：[ADR-0011](decisions/0011-weasel-foundation-restart.md)、[模块规范](product/MODULES.md)。选择 Weasel 为基础已确认；具体上游版本、扩展接口和 UI 技术尚待核查，以下为工程分工要求。

## 基础与职责

复用小狼毫已有 Windows 接入、服务通信、Rime 集成、候选与部署结构，在其上实现随译功能。不再沿用旧自建 TSF DLL／控制器／设置宿主作为产品基础。不能仅链接 librime 就声称已经基于小狼毫。

| 职责 | 边界 |
|---|---|
| 宿主接入 | 沿上游 TSF 处理组合、编辑事务、焦点、敏感范围与实际提交结果；避免在宿主加载大词典 |
| 输入与识别 | 普通方案独立可用；可选协调三语，歧义只作用于当前词；日语／英语实现需单独评估 |
| 词语资格与路由 | 判断完整词级范围与源语言；中文→日＋假名、日→英、英→中；整句不发起学习译词流程 |
| 本地词义与读音 | 离线真实词库、可靠对应义项与日语读音；缺失返回缺失，不臆造 |
| 学习提示 | 当前词的轻量展示与上屏后短时收起；不维护大词典详情界面 |
| 译词提交 | 用户明确动作、完整可靠目标、候选／词义／版本资格检查；由宿主反馈实际成功 |
| UI 与设置 | 输入窗口不抢焦点；现代独立设置；草稿、保存／取消、持久化与安全生效边界 |
| 安装与资源 | 完整离线包、版本与许可清单、升级与恢复；三个可选模块的必需资源都在包内 |

上述边界不预先指定每项各起一个进程。优先理解上游 WeaselTSF、WeaselServer、WeaselIPC、WeaselUI、部署和安装组件；在上游可维护的扩展位置工作，新增服务或 UI 进程要说明必要性。

## 输入与查询流程

普通输入产生候选；启用三语识别时由当前输入证据确定候选语言。学习／译词模块只对合格的完整词条查询。句子正常输入但没有翻译；逐词输入时每个词独立处理。查询结果绑定会话、源词范围、语言、候选、词义与配置版本。

改变候选、输入、焦点或相关配置立即使旧结果不可提交；迟到响应不能更新新词。普通确认写源词，译词动作写对应目标；提交失败保留可恢复的组合，不退化成另一种确认。读音是展示注释，不混入目标正文。

共享查询可以供多个模块使用，但模块关闭时它自己的展示、记录、计时和键位必须停止。敏感位置不查询、不记录；不读取应用全文。默认无需网络且不上传输入。

## 未决技术事项

固定上游提交、Windows 构建链、现代设置框架、候选渲染扩展点、日语／英语引擎与许可、三方向词库覆盖、词句边界、多义选择及配置协议，均须形成实测或 ADR。旧 C++20／LLVM-MinGW、Mozc、WordNet／JMdict 仅是历史经验，不自动成为新基线；语言和工具应与采纳的上游结构相容。

[旧实现经验](planning/LEGACY-LESSONS.md) 保留可迁移的教训，不保留旧类名作为强制接口。新架构未构建、未验证；不要以本文件替代运行证据。
